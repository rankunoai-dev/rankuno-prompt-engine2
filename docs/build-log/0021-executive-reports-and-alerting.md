# Cycle 0021 — Executive PDF exporter and automated alerting

**Date**: 2026-09-24
**Operator request**: "🚀 Cycle 6: Executive PDF Exporter & Automated Alerting
(building white-label client PDF reports generated by Claude Sonnet and
Slack/Email alert triggers). lets make this in detail after identfying
everything"

Decision record: ADR 0024. The four open questions were put to the operator at
the step-3 stop and answered before any code: **ReportLab** for the PDF,
**stdlib SMTP** for email, a **Sonnet-written narrative that is fact-checked**
against the computed numbers, and **only `citation_drop` enabled by default**.

## Research findings

- Everything a monthly client report states already exists as typed data:
  `InsightsView` (health, changes, actions, sentiment, cited pages),
  `PositionsView` (consolidated positions and their history) and `CostReport`.
  This cycle adds no analytics at all — only a fact sheet, a renderer, and a
  set of rules over the same data.
- `InsightChange` already carries the between-window movements
  (`flip_down`, `new_competitor`, `rank_*`), which is the alert substrate, and
  it is computed vendor-free.
- **The project payload cannot hold the alert destination.** `GET
  /api/projects/{id}` is open to any reader (ADR 0019) and the project is one
  JSON blob; a Slack webhook is a bearer credential and a recipient list is
  personal data. Both went into their own table, like `project_credentials`.
- The runtime image is `python:3.11-slim` with no `apt-get` layer and the
  operator develops on Windows, which ruled out WeasyPrint (pango/cairo/GTK)
  and Chromium long before aesthetics came into it.
- Nothing in the repo had ever sent anything outbound. Under
  `.agents/rules/risk_classes.md` that is a `write`, so the approval model is
  an operator-configured destination plus ceilings, not a per-send prompt.

## Bugs found and fixed

- **A test made a real HTTP request to Slack.** `AlertDispatcher` builds a live
  client when none is injected, and the fixture webhook is a real
  `hooks.slack.com` URL, so one test posted for real and got `404 no_team`.
  Every dispatcher in that file now gets fakes by default, with the reason in
  the helper's docstring. Worth remembering: the repo has no socket guard in
  `conftest.py`, so "all external calls are mocked" is a convention, not an
  enforcement.
- **Both new stores leaked a SQLite connection per call.** `core.sqlite.connect`
  returns a raw connection, so `with connect(path) as conn:` commits but never
  closes. The symptom was `-wal`/`-shm` files left beside the database, which
  broke `test_deploy_readiness`'s "the volume vanished" test. Both stores now
  use the same try/commit/rollback/close contextmanager as every other store.
- **`create_app` built the report store from `settings.tracker_db_path`** while
  the app's actual database is the injected `db`, so tests got a second sqlite
  file next to their own. It follows `db.path` now.
- **The report worker started a thread at app construction**, which broke a
  test asserting the poller is the only thread the server starts. It starts on
  the first submit; most processes never ask for a report.
- **`ReportStore.__init__` created directories eagerly**, leaving a `reports/`
  folder on volumes that hold no reports. Directories are made when something
  is written.
- **Chart value labels were inverted.** ReportLab stacks the first category at
  the bottom of a horizontal bar chart; the labels were drawn top-down, so
  Gemini's bar carried Google's percentage. Caught by rendering the PDF and
  looking at it, not by a test — the rows are reversed once now and colours,
  categories and labels all index the same list.
- **The body page template never activated.** `BaseDocTemplate` keeps the first
  template until `NextPageTemplate` says otherwise, so every page used the
  cover frame and no page ever drew a footer or a page number.
- **Raw platform ids reached the client PDF** ("CHATGPT_SEARCH" in an action
  title). Found by generating a report from the real demo project and reading
  it. Every string the report prints is humanised now.
- **The PNG in two test files had a bad CRC** and Pillow's `verify()` rejected
  it — which is the validation working. Replaced with a real 4×2 PNG.
- A fixture number in the narrative test was wrong (63/120 prints as 52%, not
  53%) and the fact check correctly refused it. The test was fixed, not the
  check.

## Corrections

- ADR 0024 §F says alerting runs "after `_record_crawl`". It does, but the
  destination lookup started outside the guard; anything inside the phase,
  including that lookup, is now covered by one `try`. The ADR wording is
  right, the first implementation was not.
- `docs/ROADMAP_FEASIBILITY.md` ranks "Content drafts" at 2 cycles on the basis
  that the LLM client would still need building. That client (ADR 0021) and now
  a second, prose-shaped use of it both exist, so that estimate is stale in our
  favour. Not edited here; noted for whoever picks it up.

## Explicitly not done

- **No scheduled reports.** Every report is generated on request. A monthly
  "send this to the client on the 1st" needs a scheduler entry and is its own
  change.
- **No alert for a report finishing**, and no email of a report on a schedule.
- **The `spend` and `crawl_failed` rules have no producer yet.** They are
  defined, selectable and documented, but nothing raises them: they need the
  ledger and the run outcome wired into the phase, which is a separate change.
  A reader who ticks them today gets silence, which is why the UI marks them
  operational.
- **No PDF trend chart over consolidations.** The fact sheet carries one
  window and the previous window's totals, not a series.
- **No per-window spend.** `show_spend` reports the project's whole tracked
  spend, not the spend of the crawls in that window; the ledger is not keyed by
  consolidation.
- **The report is English only**, whatever the project's locale says.
- **No live vendor call was made for the narrative.** The Anthropic path is
  covered by mocked tests; the end-to-end run against the real demo project
  used `narrative: false`, which costs nothing.
- **`ui/public/mockServiceWorker.js` is still missing**, so `VITE_MOCK=1` in a
  browser cannot register the worker (tests use the node server and are
  unaffected). Pre-existing; found while screenshotting.
